# 番茄小说网页阅读增强

在浏览器中直接阅读番茄小说网页版的完整正文，无需安装客户端，无需登录账号。

网页端默认仅放出部分章节，其余内容由「扫码下载 APP」浮层遮挡。本脚本补齐这部分正文并移除遮挡层。

除在线阅读外，还可把正文导出为本地文件：单章导出 TXT / Markdown，整本导出 FB2 / EPUB。导出文件由脚本在浏览器内直接生成，不经过第三方服务。

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 或 Violentmonkey
2. 点击 [fanqie-web-free-reader.user.js](https://raw.githubusercontent.com/xyz18950377305/fanqie-web-free-reader/main/fanqie-web-free-reader.user.js)，脚本管理器将弹出安装页，确认安装

## 使用

打开番茄小说任意章节页，地址形如：

```
https://fanqienovel.com/reader/*
```

脚本将自动以完整正文替换页面内容，并隐藏付费遮挡层。首次运行需注册匿名设备（约数秒），结果缓存在脚本管理器存储中，后续不再重复注册。

需要导出正文时，点击阅读器工具栏中的「下载」项即可打开下载面板，详见「导出下载」。

## 技术路线

### 运行流程

脚本以番茄 Android 客户端身份请求正文接口获取明文。一次完整运行的路径：

```
页面加载 / 章节切换
   ↓
从 URL 提取章节 ID（/reader/<itemId>）
   ↓
读取缓存的匿名设备 ──无──→ 设备注册→ 写入缓存
   │有
   ↓
按设置选择正文接口（默认 full），拼装 query
   ↓
生成签名头（x-argus / x-ladon / x-khronos / x-ss-req-ticket）
   ↓
请求正文接口 → 得到 base64 密文
   ↓
AES-128-CBC 解密（IV 取密文前 16 字节）→ 按魔数判定是否 gzip → 解压
   ↓
按块级标签拆成段落 → 渲染进 #fq-reader-body → 隐藏原正文与遮挡层
   ↓
记录 novel_data 中的书名 / 作者 / 封面 / book_id（供「导出下载」使用）
   ↓
当前章正文写入页面缓存（textCache）
```

正文接口出错时换另一个接口重试一次；仍失败则保留原页面，只在控制台打印 `[番茄阅读]` 日志。

### 设备注册

首次运行需要一段匿名设备注册：

| #   | 系统                                       | 接口                              | 作用                            | 失败影响      |
| --- | ---------------------------------------- | ------------------------------- | ----------------------------- | --------- |
| 1   | 设备注册 `log.snssdk.com`                    | `service/2/device_register/`    | 申请 `device_id` 与 `install_id` | 致命，流程终止   |
| 2   | 渠道校验 `ichannel.snssdk.com`               | `service/2/app_alert_check/`    | 上报设备存活                        | 可忽略       |
| 3   | 权限 `api5-normal-sinfonlinea.fqnovel.com` | `reading/user/privilege/add/v/` | 授予 30 天阅读权限                   | 可忽略       |
| 4   | 密钥 `reading.snssdk.com`                  | `reading/crypt/registerkey`     | 换取 16 字节正文密钥                  | 致命，重试 3 次 |

**系统 1 · 设备注册。** 构造一份完整的 Android 设备档案（机型、分辨率、DPI、ROM、MAC、时区等），JSON 序列化后 gzip，再经 `tt_encrypt` 加密作为请求体——以 SHA-512 派生 AES 密钥与 IV，前置魔数 `74 63 05 10 00 00` 与 32 字节随机数。响应中的 `device_id_str` / `install_id_str` 成为后续所有请求的身份。

**系统 2 · 渠道校验。** 携带系统 1 得到的 `device_id` 与 `install_id` 上报一次。脚本对其进行了容错：异常不阻断流程。

**系统 3 · 权限与密钥。** `privilege/add` 提交固定 JSON（`amount` 为 2592000 秒即 30 天，配固定 `privilege_id`），同样失败可忽略。真正的关键在 `crypt/registerkey`：把 `device_id` 按字节反转后 AES 加密作为请求体，响应中的 `data.key` 再用主密钥解出 16 字节正文密钥，脚本内以 32 位大写十六进制保存。该接口内部最多重试 3 次、间隔 1 秒。

注册结果（`deviceId` / `installId` / `secretKey`）缓存在脚本管理器存储的 `fanqie_device_v1` 下，后续运行直接复用。不涉及用户账号，不执行登录。

### 请求签名

两个正文接口共用同一套签名头。缺少任一个，上游都返回 HTTP 200 但响应体为空：

| 头                 | 构造                                                      |
| ----------------- | ------------------------------------------------------- |
| `x-khronos`       | 当前 Unix 秒                                               |
| `x-ss-req-ticket` | 同一时间戳 × 1000（毫秒）                                        |
| `x-ladon`         | 34 轮 ARX 分组密码，输入 `ts-licenseId-aid`                     |
| `x-argus`         | protobuf bean → PKCS7 → Simon → 分帧异或 → AES-CBC → base64 |

`x-argus` 的 protobuf 中第 14 个字段是 **query string 的 SM3 前 6 字节**。因此参数顺序或参数集合与签名时不一致即签名失败——脚本中签名与发送复用同一个字符串；手工构造 URL 时务必保持一致。

签名与设备注册算法移植自 [fqapp](https://github.com/ch6vip/fqapp) 的 Rust 实现。

### 正文接口

客户端提供两个正文接口。**同一章节、同一设备下，两者取回的正文逐字节相同**，差异只在协议形态与批量能力：

|       | `full`                    | `batch_full`                            |
| ----- | ------------------------- | --------------------------------------- |
| 主机    | `reading.snssdk.com`      | `api5-normal-sinfonlineb.fqnovel.com`   |
| 路径    | `/reading/reader/full/v/` | `/reading/reader/batch_full/v`          |
| 章节参数  | `item_id`（单数）             | `item_ids`（复数，逗号分隔）                     |
| 特有参数  | 无                         | `book_id=0`、`req_type=1`                |
| 单次章数  | 1                         | 实测 1 / 2 / 3 章均正常返回；**上限 30 章**，超过后静默截断 |
| 正文位置  | `data.content`            | `data[itemId].content`                  |
| 标题位置  | `data.title`              | `data[itemId].title`                    |
| 脚本内默认 | 是                         | 需手动切换                                   |

两者共用同一匿名设备身份与同一套签名头。

#### 请求与解析的分别处理

两个接口虽然内容等价，但请求拼装和响应解析走的是两条独立代码路径：

**`full`（单章）**

- 拼装：9 个公共参数 + `item_id=<章节ID>`
- 解析：正文直接取 `data.content`，标题取 `data.title`
- 判错：`data.content` 为空即抛错

**`batch_full`（批量）**

- 拼装：9 个公共参数 + `book_id=0` + `item_ids=<章节ID>` + `req_type=1`
- 解析：响应是 `{ itemId: {...} }` 字典，需先按 `itemId` 取出子对象，再读 `content` / `title`
- 判错：先查子对象 `code !== 0`，再查 `content` 是否为空

解密环节两者完全一致：`base64(iv[16] || AES-128-CBC(pkcs7(明文)))`，解出后若前两字节为 `0x1f 0x8b` 则按 gzip 解压。

> **说明**：在线阅读时脚本每次请求 `item_ids` 中只包含当前章节 ID，未使用批量接口的多章能力。真正一次带多章的是「整本下载」，见「导出下载」一节。预加载的实现见下节「预加载下一章」。

#### 公共参数

| 参数                | 值          | 说明                                     |
| ----------------- | ---------- | -------------------------------------- |
| `aid`             | `1967`     | 应用 ID                                  |
| `app_name`        | `novelapp` | 应用名（设备注册用的是 `novel`，两者不同）              |
| `channel`         | `0`        | 官方渠道                                   |
| `device_platform` | `android`  | 决定服务端按 Android 协议解析                    |
| `device_id`       | 缓存值        | 核心身份，服务端据此定位解密密钥                       |
| `device_type`     | `Honor10`  | 机型串，沿用真实客户端抓包值                         |
| `os_version`      | `0`        | 客户端确实发 `0`                             |
| `version_code`    | `66.9`     | 注意是字符串 `66.9`，与其他接口的 `6.1.5.32` 不同     |
| `novel_text_type` | `0`        | 控制正文包装形态，`1` 或省略时带 XML 声明与 `<h1>` 标题节点 |

### 预加载下一章

页面右下角面板在接口下拉框下方提供一个「提前加载下一章」开关，默认关闭，选择结果持久化保存。

开启后，脚本在渲染完当前章节后立即取回下一章并缓存。切到下一章时直接命中缓存、不再发起请求，同时接力预取再下一章，形成连续预取链。

**下一章 ID 的来源**：两个接口的响应中都含 `novel_data.next_item_id`，无需额外查询目录接口。

| 接口           | 预加载方式         | 请求增量   |
| ------------ | ------------- | ------ |
| `full`       | 单独发一次单章请求取下一章 | +1 次请求 |
| `batch_full` | 单独发一次批量请求取下一章 | +1 次请求 |

**两种接口的预加载机制相同**：都是在拿到当前章响应、从 `novel_data.next_item_id` 读到下一章 ID 后，再单独发一次请求取回下一章。区别只在用哪个接口发这个请求，请求次数一致。

`batch_full` 的 `item_ids` 每次只包含一个章节 ID，未使用批量接口的多章能力。

> **为何不能一次取两章**：下一章 ID 只出现在当前章的响应里，发请求时未拿到。若想真正批量取多章，需先通过目录接口`/api/reader/directory/detail?bookId=`拿到全书章节列表——这正是「整本下载」的做法，见「导出下载 — 目录」。

缓存最多保留最近 3 章，避免长时间阅读后无限增长。切换接口、关闭开关、执行 `__fanqieReset()` 都会清空缓存。

预加载失败不影响当前章节显示，仅在控制台提示，切章时按需重新加载。

### 切换正文接口

页面右下角固定一个设置面板，含两行控件：

- 第一下拉框：在 `full（单章）` 与 `batch_full（批量）` 之间切换，选择后当前章节立即重新加载
- 第二行开关：「提前加载下一章」

选择结果持久化保存在 `fanqie_settings_v1`。

面板挂在 `document.body` 下，不进入 `#app`，因此不受 React 渲染树影响；章节切换或整块替换阅读区后仍会保留。

任一接口失败时自动回退至另一接口。

> 这里切换的是**在线阅读**接口。整本下载另有独立的接口设置 `downloadApi`，见「导出下载 — 下载接口」。

### 单页应用适配

番茄阅读器为单页应用，目录跳转与上一页/下一页均不触发页面重载。脚本采用 `MutationObserver` 配合 800ms URL 轮询检测章节切换。

**关键约束：不得删除或改写阅读区内由 React 管理的节点。**

章节切换时，React 依据自身虚拟 DOM 对 `<p>` 与遮挡层执行 `removeChild`。若这些节点已被脚本移除，将抛出：

```
NotFoundError: Failed to execute 'removeChild' on 'Node':
The node to be removed is not a child of this node.
```

该异常由 error boundary 捕获后卸载整个 `#app`，页面变为空白。刷新页面可恢复，因为刷新为全新挂载，React 虚拟 DOM 与真实 DOM 重新对齐。

因此脚本不删除任何节点，仅执行两项操作：

- 以 CSS `display: none` 隐藏原始正文与遮挡层，节点保留在 DOM 中
- 在独立创建的 `#fq-reader-body` 容器内渲染正文

「下载」入口同样要遵守这条约束，见「导出下载 — 面板挂载」小节。

### 导出下载

工具栏中的「下载」项点开后是一个独立面板，提供单章与整本两类导出。所有文件均在浏览器内存里拼装，再由 `Blob` + `<a download>` 触发落盘，**不上传任何数据**。

| 范围  | 格式       | 文件内容                                             |
| --- | -------- | ------------------------------------------------ |
| 单章  | TXT      | 章节标题 + 正文段落，纯文本                                  |
| 单章  | Markdown | `##` 章节标题 + 正文段落                                 |
| 整本  | FB2      | 单一 XML，作者 / 书名 / 封面内嵌为 `<binary>`                |
| 整本  | EPUB     | 标准 ZIP 结构，封面页 + 书名页 + 每章一个 XHTML + nav / ncx 双目录 |

#### 面板挂载

「下载」项插在阅读器工具栏 `.reader-toolbar` 内，用与站点一致的 `.reader-toolbar-item` 样式（图标 + 文字上下排列），点击互斥地展开 / 收起面板。

面板挂在 `document.body` 下，**不进入 `#app`**，因此不受 React 渲染树影响——这正是上一节「不得改写 React 节点」约束的延续：脚本只向工具栏 `appendChild` 自建节点，绝不修改其既有子节点。

工具栏由 React 管理，展开 / 收起或重渲染都会把下载项移除，800ms 轮询与每次 `run()` 都会调用 `ensureDownloadButton()` 补齐；面板本身同理，被移除后重新打开即可。

面板点击外部区域自动关闭，监听器绑在 `document` 的捕获阶段，避免站点自身的 `stopPropagation` 拦截。

**关闭面板不等于中断下载**：队列、进度与状态全在 `downloadWholeBook()` 的异步函数作用域内，与面板是否挂载无关。

#### 目录

整本下载需要全书章节列表，取自站点自身的目录接口，不需要额外身份：

| 项   | 值                                                                                       |
| --- | --------------------------------------------------------------------------------------- |
| URL | `https://fanqienovel.com/api/reader/directory/detail?bookId=<bookId>`                   |
| 方法  | GET，无签名头                                                                                |
| 解析  | `data.chapterListWithVolume`，结构为 `[[{itemId, title, volume_name}, ...], ...]`，同时也兼容对象形式 |
| 输出  | 按卷顺序展开的扁平数组，每项 `{ itemId, title, volume }`                                              |

`bookId` 优先取当前页正文响应里的 `novel_data.book_id`（已缓存在 `currentBookId`）；没有时先取一次当前章再读。

目录标题是导出时最可靠的标题来源：**目录标题优先，接口返回的标题仅作兜底**。接口标题在部分章节缺失或带多余前后缀，合并逻辑见 `withMetaTitle()`。

#### 整本下载流程

```
点击「整本 FB2 / EPUB」
   ↓
取 bookId → 取目录 → 得到 N 个章节 ID
   ↓
先吃缓存（textCache + 预加载缓存），剩下的进待取队列
   ↓
循环：从队首切一批（DOWNLOAD_BATCH_SIZE = 10）
   ↓
按下载接口取正文（默认 batch_full；可切 full 逐章）
   ↓
成功 → 写入结果集；失败 → 翻回队尾，无限重排
   ↓
重复直到队列为空（或用户取消）
   ↓
按目录顺序排序 → 取封面 → 生成 FB2 / EPUB → 触发浏览器下载
```

进度显示为 `attempted/total`：`attempted` 每次尝试都 +1，`total` 在某章失败并重排时 +1。

#### 下载接口

下载使用**独立的接口设置** `downloadApi`，与在线阅读接口 `api` 互不影响，默认 `batch`。跨页持久化在 `fanqie_settings_v1` 中。

| 取值          | 面板文案             | 走哪个请求                                    | 特点                        |
| ----------- | ---------------- | ---------------------------------------- | ------------------------- |
| `batch`（默认） | `batch_full（批量）` | `fetchBatchMulti()`，一次 `item_ids` 带 10 章 | 往返次数少，整本下载依赖此能力           |
| `full`      | `full（单章）`       | 逐章 `fetchByFull()`                       | 每章一次请求、天然逐章容错，适合批量持续失败时排查 |

下载中下拉框变灰不可选，避免同一次导出前后数据来自不同接口。

#### 批量上限与限流

这是整本下载最关键的两个上游约束，均由实测得到：

- **硬上限 30 章**：单次请求 `item_ids` 超过 30 章时，上游只返回前 30 章且**不报错**（静默截断）。因此 `fetchBatchMulti()` 内部按 `BATCH_HARD_LIMIT = 30` 主动分片，超出的部分另发请求。
- **连续请求会被限流**：连续快速请求时，响应里会随机缺失部分章节（实测连续请求 100 章会缺 30~60 章）。因此分片之间固定 `sleep(1200)`。

`DOWNLOAD_BATCH_SIZE` 取 10 而不是 30，是在「往返次数」与「单批失败重试成本」之间折中：一个 10 章的批次失败，只需重排这 10 章。

#### 队列与重试

设计目标是**尽量不丢章**，因此重试策略是「外层无限重排 + 逐级退避」，而不是有限的固定重试次数：

| 层级            | 策略                                       |
| ------------- | ---------------------------------------- |
| 单章（在线 / 单章导出） | 最多 3 次（`DOWNLOAD_RETRY`），间隔 800ms × 尝试次数 |
| 批次请求本身抛错      | 最多 2 次，间隔 1000ms × 尝试次数                  |
| 单章在整本导出中失败    | 不原地重试，翻到队尾；由外层队列统一重排                     |
| 一轮内所有批次均无进展   | 视为被限流，`1s → 2s → 4s → …` 指数退避，上限 30s     |
| 有进展           | 每批结束固定 `sleep(200)` 轻微限速                 |

`full` 模式不做内层重试，只靠外层队列重排——否则「内层 3 次 × 外层无限」会把请求量成倍放大。

取消标记在每一批、每一章处理前都会检查（`checkCancelled()`），取消后立即抛错，不继续刷进度；走到导出阶段前还会再检查一次，**取消即终止，不生成残缺文件**。

#### 互斥与取消

`downloading` 是一个非空即锁的字符串（如 `整本 EPUB`）。同一时刻只允许一个导出任务：

- 其他下载入口直接忽略点击，状态栏提示「正在下载中（…），请稍候」
- 下载中所有按钮变灰、下载接口下拉框禁用
- 面板提供「取消」按钮（仅下载中显示），置位 `cancelRequested`

重复触发的危害不只是浪费流量：两份任务并发跑同一本书，请求频率翻倍，很容易触发风控。

面板若在下载途中被重建（React 重渲染或手动开关），会按当前锁状态重新同步一次按钮禁用态与状态栏。

#### 生成 TXT / Markdown

单章的 TXT 与 Markdown 直接复用已取回的正文，**不额外发请求**——当前章在 `run()` 时已写入正文缓存 `textCache`，命中预加载缓存的章节也直接复用。

正文由 `htmlToLines()` 拆行：`<br>` 转为换行，`<h1>` 与块级标签（`p` / `div` / `article` / `header` / `footer`）转为换行，剥掉其余标签，逐行去空白与空行，再反转义 `&nbsp;` `&lt;` `&gt;` `&amp;` `&quot;` `&#39;`。这与页面渲染用的是同一个函数，因此**导出内容与阅读所见一致**。

单章不写书名，只写章节标题；接口未返回标题时按「第 N 章」兜底。

#### 生成 FB2

FB2 是单文件 XML，章节放在 `<body>` 内、每章一个 `<section>`，作者与封面写在 `<description>` 里：

```
FictionBook
├── description
│   ├── title-info        book-title / author / coverpage / lang=zh
│   └── document-info     program-used = fanqie-web-free-reader
├── body
│   ├── <title>           书名
│   └── <section id="chN"> 每章一个，含 <title> 与逐段 <p>
└── <binary id="cover-image">  封面原始字节的 base64
```

封面以 `<binary content-type="image/…">` 内嵌，`coverpage` 通过 `l:href="#cover-image"` 引用。所有文本节点经 `escapeXml()` 转义，避免正文里的 `&` `<` 破坏 XML。

作者缺失时写「佚名」。

#### 生成 EPUB

EPUB 是 ZIP 容器。为了不引入第三方库、也不依赖 `CompressionStream` 在不同浏览器版本上的差异，脚本内置了一个**只做 store（不压缩）的最小 ZIP 写入器** `makeZip()`：

- `mimetype` 必须是第一个条目、必须是 store 方式，内容固定为 `application/epub+zip`
- 本地文件头 + 中央目录 + EOCD 三段手工拼装，大小与 CRC32 均由脚本自算
- 文件名标记 `0x0800`（UTF-8），避免中文文件名乱码

EPUB 规范允许条目不压缩，因此 store 方式合法，代价只是文件体积略大。

生成的目录结构：

```
mimetype
META-INF/container.xml          → 指向 OEBPS/content.opf
OEBPS/content.opf               → OPF 3.0 包文档，metadata / manifest / spine
OEBPS/nav.xhtml                 → EPUB 3 导航（epub:type="toc"）
OEBPS/toc.ncx                   → EPUB 2 兼容目录
OEBPS/cover.jpg|png|gif|webp    → 封面原图（取不到时省略）
OEBPS/cover.xhtml               → 封面页（首个 spine 项）
OEBPS/titlepage.xhtml           → 书名 + 作者
OEBPS/chapter<N>.xhtml          → 每章一个文件
```

`unique-identifier` 取 `fq-<bookId>`，`dcterms:modified` 取当前 UTC 时间（EPUB 3 必填）。

> **大章数下的性能细节**：不能用 `concatBytes(...parts)` 拼装 ZIP——章节数上万时 `parts` 长度可达数万，展开运算符会撞上 V8 的参数个数上限，抛 `RangeError: Maximum call stack size exceeded`。因此这里先算出总长、一次性预分配 `Uint8Array`，再逐段写入，与章数无关。

#### 封面

封面 URL 来自正文响应的 `novel_data.thumb_url`（带签名的静态资源地址），直接 GET 下载原图，图片类型按魔数判断：

| 魔数前缀    | 判定        |
| ------- | --------- |
| `89 50` | PNG       |
| `47 49` | GIF       |
| `52 49` | WebP      |
| 其他      | 按 JPEG 处理 |

取不到封面不影响导出，FB2 省略 `coverpage` 与 `<binary>`，EPUB 省略封面页与封面图，其余部分照常生成。

#### 落盘

导出统一走 `saveBlob(filename, bytes, mime)`：`Blob` → `URL.createObjectURL` → 隐藏 `<a download>` → `click()` → 立即移除 `<a>`。

**不能固定 2 秒后 `revokeObjectURL`。** 整本导出可能是几十上百 MB，浏览器写盘尚未完成就撤销 URL，会导致下载中断或得到 0 字节文件。脚本把撤销延后到 60 秒，给大文件足够的落盘时间。

文件名经 `sanitizeFilename()` 处理：把 `\ / : * ? " < > |` 替换为 `_`，压缩空白，截断到 80 字符，空名回退为 `book`。

#### 缓存与内存

| 缓存                 | 上限    | 用途               | 清空时机                          |
| ------------------ | ----- | ---------------- | ----------------------------- |
| 预加载缓存 `prefetched` | 3 章   | 切章免请求            | 切接口 / 关开关 / `__fanqieReset()` |
| 正文缓存 `textCache`   | 400 章 | 单章导出免请求、整本导出先吃缓存 | 超出上限时按插入顺序淘汰最早的               |

整本导出先扫一遍这两级缓存再排队，命中的章节完全不发请求。400 章的上限覆盖了长篇的整本导出场景，又不会在长时间阅读后无限增长；`__fanqieReset()` **不清空**该缓存，切换阅读接口同样不清空——正文按设备密钥解密，结果与阅读接口无关。

#### 错误处理

| 情况           | 表现                             |
| ------------ | ------------------------------ |
| 拿不到 `bookId` | 状态栏「失败：拿不到书籍 ID」               |
| 目录为空         | 状态栏「失败：目录为空」                   |
| 没有取到任何章节     | 状态栏「失败：没有取到任何章节」               |
| 用户取消         | 状态栏「已取消」，控制台 `[番茄阅读] 整本下载已取消`  |
| 其他失败         | 状态栏「失败：<原因>」，控制台 `[番茄阅读] …` 警告 |

单章导出失败只影响该章，不动页面；整本导出失败或取消都不会生成残缺文件，已取回的正文仍留在 `textCache` 中，重试时自动复用。所有错误文案只走状态栏与控制台，不弹窗、不打断阅读。

## 常见问题

**脚本未生效**

打开开发者工具（F12）检查控制台是否存在 `[番茄阅读]` 前缀的日志。若无输出，确认脚本管理器已启用该脚本且允许在当前域名运行。

**提示「正文接口返回空响应」**

签名被拒绝或设备身份失效。打开脚本管理器菜单，点击「清除设备缓存（重新注册）」即可，脚本会立即以新设备重新拉取当前章节。

也可在控制台执行 `__fanqieReset()` 后刷新页面。

**是否会导致账号风险**

脚本使用匿名设备身份，不涉及用户账号，不执行登录。但请注意请求频率，避免触发风控。

**工具栏里没有「下载」项**

下载项插在 `.reader-toolbar` 内，工具栏由 React 管理，收起或重渲染时会被移除。脚本每 800ms 补齐一次，若仍未出现，稍等片刻或切换一次章节即可。

**整本下载卡在某个进度不动**

说明当前批次被限流，响应里连续缺失章节。脚本会按 1s → 2s → 4s → … 指数退避，最长 30s 后自动重试，一般会自行恢复。若长时间无进展，点击「取消」后把下载接口切到 `full（单章）` 再试一次，可以定位是接口问题还是网络问题。

**下载的 EPUB / FB2 打不开或封面缺失**

封面是可选内容，取不到时不影响正文，文件仍应能正常打开。若文件本身损坏（例如 0 字节），多与浏览器在写盘完成前被打断有关，重新导出一次即可；脚本已把 `revokeObjectURL` 延后到 60 秒以避免该问题。

**下载会不会占用很多内存**

整本导出时全部章节与生成的文件都在内存中拼装，几十 MB 的书对现代浏览器没有压力。但超长篇小说（数千章）导出 EPUB 时瞬时内存占用会明显上升，建议在桌面端操作，不要在移动端浏览器里导出整本。

## 调试接口

脚本管理器菜单提供「清除设备缓存（重新注册）」，等价于下列调用。

```js
__fanqieReset()              // 清除设备缓存，下次运行重新注册
__fanqieApi('full')          // 切换至单章接口
__fanqieApi('batch')         // 切换至批量接口
__fanqiePrefetch(true)       // 开启提前加载下一章
__fanqiePrefetch(false)      // 关闭提前加载下一章
```

下载接口（`downloadApi`）目前只能在下载面板的下拉框中切换，未导出为 `__fanqie*` 函数。需要脚本化切换时直接改写设置：

```js
GM_getValue('fanqie_settings_v1')   // 读取当前设置
GM_setValue('fanqie_settings_v1', { ...GM_getValue('fanqie_settings_v1', {}), downloadApi: 'full' })
```

`downloadApi` 只影响下一次发起的整本下载；已开始的任务沿用启动时的取值。
